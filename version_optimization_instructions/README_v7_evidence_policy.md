# v7：严格确认身份，按出处组织证据，允许回答自然改写

基于已安装v6（或已安装v5并一并复制本包诊断模块）的增量补丁。不改数据、不重建索引、不引入额外LLM调用。先备份本地修改，再合并包内同名文件。

## 这次如何把握“度”

AI最终回答可以总结、换说法、调整展示结构，并非必须逐字一致。之前v5要求“整段概括后的图步骤包含在原文里”，把合理改写和错误内容混为一谈，造成过度回退；那是检索证据准入规则，并不是此前在检测AI最终答案逐字一致。

v7将三层分开：

1. 身份边界严格：规范菜名唯一、图节点ID正确、步骤所有归属只能是目标菜谱、序号合法。违反这些条件仍回退，不拿高相似度覆盖身份错误。
2. 证据边界可解释：图步骤经过概括不再让整道菜失败。明确标为unverified_summary，仅表示尚未独立核验，不是“数据错误”；完整目标原文仍可回答。摘要本身不作为新增事实输入。
3. 最终表达允许改写：模型依照有出处的原文及摘录组织语言。食材、用量范围、份数公式、可选条件、否定和顺序依赖仍需保持；提示词要求保留改编说明，来源核对不代表专业审核。

## 不用相似度阈值直接放行

本版不声称靠纯规则证明任意自然语言等价，也不增加一次LLM来判断。能识别的“描述：”等旧索引包装先分字段，能对应原文的内容转换成完整原文行（source projection），不把整个带有未核验工具/时间/份量的chunk原样投喂。

例如候选片段只有“加入花生”，原文是“可选：加入花生，过敏者不要添加”，送给模型的是后者整行，防止丢掉条件或否定。候选只写“鸡蛋=1.5个”，若对应原文还含“*份数，向上取整”，保留整行公式。新匹配不会像旧归一化那样把1.5、15、1-5、1/5混同。

这个保护仅作用于给模型的证据，不是生成后自动语义审查。模型最终仍可能出错，需要真实回答抽查/回归验证。原文内容本身是否权威仍是数据治理问题，不能由“有出处”推导“专业正确”。

## 结构化片段具体处理

- step_envelope：只解析“描述”正文；方法/工具/时间等推断字段不直接放行。可核对的部分转换为带条件的原文行；其余摘要记录为未核验，不把整道菜拒绝。
- derived_fields：自动计算/压缩的食材用量、份量、时间等不代替原始公式；保留完整原文作为依据，不盲目删掉标签就接受数值。
- tags/plain：能明确定位的较短内容可转换为整行原文；无法核验则暂不采用，不认定库里没菜。
- 任意ID/parent_id/名称/类型不符：identity_rejected，仍严格拦截。

同一chunk可以部分有依据、部分未核验；送入模型的是有依据的原文摘录，而不是该chunk的整段概括。原始目标文档始终保留，所以摘录不完整不会替代完整做法。原文顺序控制摘录排列，图摘要的反序不重排原文；结构序号缺失或重复仍拦截。

## 状态语义

- graph_verified：身份/结构通过，图步骤均可定位原文；生成证据仍为原文投影，不直接复制其他推断属性。
- graph_scoped_source：身份/结构通过，但部分或全部摘要未独立核验。保留原文回答，不标为整体故障。
- local_fallback：图身份/结构不可靠或数据库服务异常，沿用v4原文兜底。
- vector_status=source_projected：有片段可转换为原文依据。
- derived_content_withheld：只取到了暂不采用的概括/衍生字段，不是跨菜谱错误。
- contains_identity_rejections：存在身份不符片段，需检查索引数据。

accepted_chunks改为可用原文投影片段数；rejected_chunks只计身份拒绝；withheld_chunks计无可用原文投影的片段。不要直接与旧v5的rejected_chunks统计口径混比。
