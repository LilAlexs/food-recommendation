# v10：会话要求与单道菜要求分开管理

## 对应优化清单

推进路线图06“多轮会话状态”：结构化要求、作用范围、覆盖/取消、随话题变化的生命周期。
以用户已验证油/葱/蚝油追问的v9.1为基础。本包是v9.1增量，不能直接装到原版或v7。
未完成清单10“食材约束推荐”的候选硬过滤与约束满足率评测，不能把状态传递成功等同于推荐一定满足所有要求。

## 之前的问题

Web入口从历史里搜索“不放/过敏/分钟/人份”，把命中原句再次拼给模型。
它没有区分“这道菜不放辣椒”和“我一直不吃辣”；换菜可能带上旧菜条件，取消后也可能重新从旧历史找回。历史最多10条还会让长期要求消失。

## 本次实现

新增session_constraints.py，采用结构化scope/kind/value/source保存明确要求。
- session：本次会话持续有效，换菜不清除；不代表跨会话用户画像。
- dish：绑定当前菜谱ID；换菜或离开单菜话题失效，之后再回到旧菜也不自动复活。
- 明确当前菜/会话范围的添加、删除、清空；份数/用时在各自范围内覆盖，当前菜数值优先于会话数值。
- 用户声明过敏作为会话要求保存，不因“取消这道菜的限制”丢失；明确清除本次会话所有限制才会清除会话要求。
- 无当前菜且范围不明确，或只说“取消限制”时澄清，不假定清除全部。
- 纯要求更新直接确认，不调用LLM、不清除当前菜谱、不写入问答历史。
- 确认单菜的问题与普通推荐查询都带上适用的结构化要求，删除原来重复扫描历史原句的两套逻辑。
- 要求变更清除本会话答案缓存；有要求时不读写答案缓存，防止返回旧条件下的答案。单会话/全部缓存清理同步清除要求。
- 普通聊天与SSE共用入口，保持v9.1用量追问逻辑。

不是继续按固定食材名单写规则。食材值从明确语句提取，支持芝麻、芹菜等不同名称；状态更新采用可验证边界。当前采用有限语法解析，不能保证任意口语都能保存。没有识别的复杂表达不会获得“已更新要求”的专用确认，但生成模型仍可能给自然语言回应；不能把普通回答中的口头承诺当作已保存状态。

## 当前支持的明确表达

- 我一直不吃辣 / 以后所有菜都不放葱：会话要求。
- 我花生过敏 / 我对花生过敏：会话过敏要求。
- 红烧鱼确认后：这道菜不放辣椒 / 不放辣椒：当前菜要求。
- 不放花生的宫保鸡丁怎么做：当前问题保留原意，确认目标后保存为该菜要求。
- 取消这道菜的限制：仅清除当前菜要求。
- 这道菜取消不放辣椒要求：仅移除该项当前菜要求。
- 清除本次会话的所有限制：仅清除会话要求；若同时还有当前菜要求，仍会保留。
- 这道菜做两份 / 这道菜改成三份：更新当前菜份数。
- 所有菜最多20分钟 / 这道菜最多10分钟：保存用时要求，不代表原菜谱能在该时限完成。

过敏不是医疗判断，本模块仅保留用户声明；不自动判断衍生成分、交叉接触或替代配方。
若要求与原方冲突，提示模型明确说明冲突；不应把删料后的做法称为原方。尚未实现最终输出逐条校验与候选食材硬过滤，因此不承诺自动避免所有违反要求的回答。

## 安装

1. 备份 E:\work\What-to-eat-today-main\rag_modules 整个目录。
2. 把包内rag_modules、tests合并进v9.1目录，覆盖同名文件，保留其余文件。
3. 不修改food-recommendation-main原始备份，不改数据库、索引、模型配置、前端、依赖与Nginx。
4. 在PowerShell执行：

```powershell
cd E:\work\What-to-eat-today-main
docker-compose -f docker-compose.yml -f compose.query-debug.yml restart backend
```

此前Python目录已挂载，不用build、不重建索引。restart会清空内存会话及约束状态。

```powershell
curl.exe --noproxy "*" --max-time 10 http://127.0.0.1:8000/health
```

正常后打开http://127.0.0.1，新建会话。仅restart一般无需重启Nginx。

## 验收建议

会话A：
1. 红烧鱼怎么做？
2. 这道菜不放辣椒。
3. 油需要多少？（仍应取红烧鱼30-50ml，并带上当前菜要求）
4. 番茄炒蛋怎么做？（不再继承红烧鱼的不放辣椒要求）

会话B：
1. 我一直不吃辣。
2. 红烧鱼怎么做？
3. 番茄炒蛋怎么做？（会话要求继续存在）
4. 清除本次会话的所有限制。
5. 番茄炒蛋怎么做？（不再恢复旧要求）

会话C：
1. 番茄炒蛋怎么做？
2. 这道菜做两份。
3. 盐需要多少？（资料总盐量3-4g，蛋液2g，其余最后加）

另外可验证过敏声明遇宫保鸡丁时，应说明原方花生与要求冲突，不能宣称原方无花生。不必反复重跑完整性能评测。

可复制trace：
```powershell
docker cp what-to-eat-backend:/tmp/query_debug.jsonl .\query_debug_v10.jsonl
```

新增constraint_update（变更范围/动作数量）与constraint_context（作用范围数量）事件，不主动记录食材或完整用户声明。纯更新确认可在网页看到当前生效要求。
